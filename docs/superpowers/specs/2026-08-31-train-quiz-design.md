# でんしゃクイズ 設計仕様書

作成日: 2026-08-31
ステータス: レビュー中

## 1. 概要

4歳児(ひらがな読み習得中)向けの、電車の名前当てクイズアプリ。
電車の写真を見て、ひらがなの4択から名前を選ぶ。iPad(第6世代)のSafariから
「ホーム画面に追加」して使う **PWA(オフライン完全対応のWebアプリ)** として実装する。

世界観は「1ゲーム = 1本の電車の旅」。モードの代表電車が駅を出発し、
1問正解するごとに次の駅へ走り、全問終えると終点に到着して結果発表となる。

### 目的・成功基準

- 子どもがひとりで操作でき、電波のない外出先(新幹線・車内等)でも遊べる
- ひらがなを読む練習になる(選択肢はすべてひらがな)
- 必ず「できた!」で終われる(不正解でも同じ問題に再挑戦できる)

## 2. 利用環境

| 項目 | 内容 |
|---|---|
| 端末 | iPad 第6世代(iPadOS 17 / Safari) |
| 配布 | Safariで開き「ホーム画面に追加」→ 全画面スタンドアロン起動 |
| オフライン | 必須。全素材をService Workerでプリキャッシュ |
| 画面向き | 横向き(ランドスケープ)に最適化。縦でも崩れない程度に対応 |
| 利用者 | 子ども(4歳)がプレイ、親が設定 |

## 3. 画面仕様

### 3.1 画面遷移

```
スタート画面
   │ はじめる
   ▼
ゲーム選択 ──(将来: さんすう)
   │ でんしゃクイズ
   ▼
モード選択(しんかんせん/とっきゅう/ざいらいせん/してつ/ぜんぶ)
   │
   ▼
出発演出 ──タップでスキップ可
   ▼
┌─ 問題画面 ─────────────────┐
│  正解 → 幕間演出(電車が次の駅へ走る) │ × N問
│  不正解 → 同じ問題に再挑戦            │
└──────────────────────┘
   ▼
到着演出(終点のホームに到着)
   ▼
結果画面(ドアが開く → 車掌さん祝福「◯もんせいかい」)
   ├ もういちど → 同モードで再出題(出発演出から)
   └ もどる   → モード選択へ
```

- 設定画面は、スタート画面の隅の歯車アイコンを **3秒長押し** で開く(子どもの誤操作防止)。

### 3.2 各画面の詳細

#### スタート画面
- タイトルロゴ(仮称「でんしゃクイズ」。名称は後で決定)
- 犬の車掌さん(通常ポーズ)
- 大きな「はじめる」ボタン
- 右下に小さめの歯車アイコン(3秒長押しで設定画面へ)

#### ゲーム選択画面
- ゲームをカード形式で表示。現時点は「でんしゃクイズ」1枚のみ
- 将来「さんすう(足し算・引き算)」を追加する前提で、複数カードを並べられるレイアウト・データ構造にしておく
- 準備中のゲームは表示しない(押せないカードは子どもが混乱するため)

#### モード選択画面
- 5つの大きなボタン: **しんかんせん / とっきゅう / ざいらいせん / してつ / ぜんぶ**
- 各ボタンにはモードの代表電車のイラスト(横向きSVG)とひらがなラベル
- 戻るボタン(ゲーム選択へ)

#### 出発演出
- 背景: 駅のホーム
- モードの代表電車が入線 → ドアが閉まる → 「しゅっぱつ!」の文字と発車音とともに走り出す
- 所要 約3秒。画面タップでスキップ可

#### 問題画面
- **背景: 駅のホーム**(全問共通の背景イラスト)
- 上部: 問題の電車の写真を大きくカード状に表示
- 上端: 進捗表示 —— 路線図風のバー(駅の点がN個並び、現在位置に代表電車のアイコン)
- 下部: ひらがな4択ボタンを 2×2 グリッドで大きく配置(タップ領域は最低 120×80pt 目安)
- 正解タップ時:
  - 画面中央に大きな **赤い◯** と「**せいかい**」の文字
  - 犬の車掌さん(喜びポーズ)表示 + 警笛「ファーン!」の効果音
  - 約1.5秒後、自動で次へ(次の問題がある場合は幕間演出、最終問題なら到着演出へ)
- 不正解タップ時:
  - 画面中央に大きな **青い✕** と「**もういっかい**」の文字
  - 犬の車掌さん(困り顔ポーズ)表示 + 不正解の効果音
  - 約1.5秒後、**同じ問題に戻る**。選択肢の内容・配置はそのまま、押した誤答ボタンはグレーアウトして押せなくする(消去法で最後は必ず正解できる)
- 演出表示中は全ボタンを無効化(連打対策)

#### 幕間演出(問題間)
- 代表電車が駅から次の駅へ走るアニメーション(横スクロール、約2秒)
- 進捗バーの電車アイコンが1駅進む
- タップでスキップ可

#### 到着演出
- 最終問題の正解後、代表電車が終点のホームに到着し停車する演出
- そのまま結果画面へつながる(ドアが開く演出は結果画面側)

#### 結果画面
- 電車のドアが開くアニメーション → 中から犬の車掌さん(祝福・ばんざいポーズ)が登場
- 「**◯もんせいかい**」(分母も表示: 「10もんちゅう 8もんせいかい」等)
- 全問一発正解のときは特別演出(はなまる+紙吹雪など)
- ボタン: 「もういちど」(同モードで再出題) / 「もどる」(モード選択へ)

#### 設定画面(親用)
- 入り方: スタート画面の歯車を3秒長押し
- 項目:
  1. **もじの表記**: ひらがな / ふつう(カタカナ・漢字交じり) — 既定はひらがな
  2. **もんだいの数**: 5問 / 7問 / 10問 — 既定は5問
  3. **おと**: オン / オフ — 既定はオン
  4. **写真クレジット**: 使用写真の撮影者・ライセンス一覧(スクロール表示)
- 設定はlocalStorageに保存

## 4. ゲームロジック仕様

### 4.1 出題

- 選択したモードのカテゴリに属する電車プールから、設定問題数ぶんを**重複なしランダム抽選**
- 「ぜんぶ」モードは全カテゴリ混合プール
- プールが問題数に満たない場合は全問出題(その数で終了)

### 4.2 選択肢生成

- 正解1 + 誤答3 の4択。誤答は**同じカテゴリ**の別の電車からランダム抽選
  (「ぜんぶ」モードでは正解と同カテゴリを優先し、足りなければ全体から)
- 表示名(現在の表記設定での文字列)が正解と同一・重複する電車は誤答から除外
- 4択の配置はランダム

### 4.3 再挑戦とスコア

- 不正解時は同じ問題・同じ選択肢配置で再挑戦(押した誤答はグレーアウト)
- スコアは **初回タップで正解した問題のみ** カウント
- 何度間違えても最終的に正解して次へ進むため、ゲームは必ず完走できる

## 5. データ仕様

### 5.1 電車データ(trains.json)

```json
{
  "id": "e5-hayabusa",
  "name": {
    "hiragana": "はやぶさ",
    "normal": "はやぶさ(E5系)"
  },
  "category": "shinkansen",
  "image": "images/trains/e5-hayabusa.webp",
  "credit": {
    "author": "撮影者名",
    "license": "CC BY-SA 4.0",
    "source": "https://commons.wikimedia.org/..."
  }
}
```

- `category`: `shinkansen` | `express` | `local` | `private`
- `name.hiragana`: 長音は「ー」を使用(例: どくたーいえろー)
- `name.normal`: 実際の表記に近い形(カタカナ・漢字・形式名併記可)

### 5.2 モードデータ(modes.json)

```json
{
  "id": "shinkansen",
  "label": { "hiragana": "しんかんせん", "normal": "新幹線" },
  "categories": ["shinkansen"],
  "heroTrain": "images/hero/shinkansen.svg"
}
```

- `heroTrain`: 代表電車の横向きイラスト。モード選択ボタン・出発/幕間/到着演出で共通使用
- 「ぜんぶ」モードは `categories` に全カテゴリを持ち、代表電車は新幹線と同じ(仮)

### 5.3 設定データ(localStorage)

```json
{ "notation": "hiragana", "questionCount": 5, "sound": true }
```

## 7. 素材仕様

### 7.1 電車写真

- 出典: Wikimedia Commons を第一候補(CC BY / CC BY-SA / パブリックドメイン)。その他ライセンス上利用可能なフリー素材も可
- 加工: WebP変換、長辺800px程度に縮小、1枚150KB前後を目安
- クレジット: 撮影者名・ライセンス・出典URLを電車データに保持し、設定画面に一覧表示(CC BYの表示義務を満たす)

### 7.2 犬の車掌さん(親が生成AIで用意)

必要ポーズ(同一キャラクター・背景透過PNG・1024px四方目安):

| # | ポーズ | 使用場面 |
|---|---|---|
| 1 | 通常(にっこり立ち姿) | スタート画面 |
| 2 | 喜び(ばんざい・笑顔) | 正解時 |
| 3 | 困り顔(眉下がり・首かしげ) | 不正解時 |
| 4 | 祝福(紙吹雪・大きくばんざい) | 結果画面 |

生成プロンプト案(ChatGPT / Gemini等に投入):

> 子ども向けアプリのマスコットキャラクター。柴犬の車掌さん。紺色の鉄道制服と制帽、笛を首から下げている。絵本風のフラットでかわいいイラスト。全身、正面向き、背景透過。にっこり笑って立っているポーズ。
>
> (2枚目以降は同じチャットで)同じキャラクター・同じ画風のまま、ポーズだけ「両手を上げて大喜び」に変えてください。…以下ポーズ差し替え

### 7.3 走行演出用の電車イラスト(heroTrain)

- モードごとに1つ、**横から見たシンプルな電車イラスト(SVG)** を用意(計5点)
- まず Claude がSVGで作成。品質が不足なら生成AI画像(横向き・背景透過PNG)に差し替え可能な作りにする
- 代表電車(仮): しんかんせん=はやぶさ / とっきゅう=あずさ / ざいらいせん=やまのてせん / してつ=ロマンスカー / ぜんぶ=はやぶさ

### 7.4 効果音

| 音 | 使用場面 | 調達 |
|---|---|---|
| 警笛「ファーン!」 | 正解時 | 効果音ラボ等の無料素材(商用可・クレジット不要のもの優先) |
| 不正解音(「ブブー」系のやわらかい音) | 不正解時 | 同上 |
| タップ音 | ボタン押下時 | 同上 |
| 発車音(ベル or 走り出し音) | 出発演出 | 同上 |
| 到着音(ブレーキ・停車) | 到着演出 | 同上 |
| ファンファーレ | 結果画面 | 同上 |

- 音はすべてユーザーのタップを起点に再生する(iOS Safariの自動再生制限に抵触しない設計)
- 設定「おと: オフ」時は全効果音をミュート

### 7.5 背景

- 駅のホーム背景イラスト1点(問題画面・出発/到着演出で共用)。SVGまたは生成AI画像

## 8. 技術仕様

| 項目 | 内容 |
|---|---|
| スタック | Vite + TypeScript(UIフレームワークなし)。単一ページ内で画面をDOM切り替え |
| PWA | Web App Manifest + Service Worker。**全素材(HTML/JS/CSS/画像/音声/JSON)をインストール時にプリキャッシュ**し完全オフライン化 |
| ホスティング | GitHub Pages(無料・HTTPS) |
| 容量目標 | 全体で30MB以内(iOSのキャッシュ退避リスクを下げる) |
| 状態保存 | 設定のみlocalStorage。成績の永続化はしない(スコープ外) |
| テスト | 出題抽選・選択肢生成・スコア計算のロジックを Vitest でユニットテスト |
| 更新 | オンライン時にService Workerが新バージョンを検知し、次回起動時に更新 |

### 既知の制約

- iOSのPWAは長期間未使用だとキャッシュが削除されることがある。その場合はオンラインで一度開き直せば復旧する。頻発して困る場合は、同じコードをCapacitorでラップしてネイティブアプリ化する(将来の選択肢として温存)

## 9. 将来拡張(今回スコープ外)

- さんすうゲーム(足し算・引き算)— ゲーム選択画面に追加
- 成績の記録・親向けレポート

- 効果音の音量調整(オン/オフのみ)
- 多言語対応
- App Storeへの公開
